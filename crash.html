當機

當機是最容易「認出來」的 bug：遊戲直接關掉，沒有人會爭論它算不算錯。真正的難題在認出之前和之後：怎麼把遊戲玩到當掉、怎麼依一份模糊的回報重新走到當機那一刻，以及收到幾萬份回報後先修哪一個。

示意情境

一份 Minecraft 的回報寫著：「我在下界蓋了一座傳送門，帶著一箱物品跳進去，回到主世界的瞬間遊戲就關了。」報告裡有一段 stack trace，但沒有存檔、沒有確切步驟，遊戲版本也比現在舊了三版。開發者要先重現它，才能開始修。

問題怎麼定義

Truelove 等人把 Crash 定義為「遊戲當掉或被迫關閉」。在他們標記的 12,122 筆修正裡，當機出現 580 次，其中 219 次出現在緊急更新，比例 38%，是所有類別裡最高的；它也是最常在後續版本再次出現的類別。

當機的研究可以照時間軸分成三段：開發中讓自動化程式把遊戲玩到當掉；收到回報後依玩家的描述重新走到當機那一刻；上線後從大量當機紀錄裡判斷先修哪一個。三段用的方法完全不同。

現在的做法

流派一 · 自動探索 agent（開發中）

讓 agent 自己玩，玩到出事為止

這一派的共同想法是：讓 agent 自動玩遊戲，同時用內建的自動判定（oracle）標出異常，例如遊戲是否當掉、任務是否卡住。差別在於誰來決定下一步操作：早期用強化學習，近年改用 LLM。

強化學習的代表是 Wuji。Wuji（ASE 2019，網易伏羲與天津大學等）先分析了 4 款商業遊戲的 1,349 個真實 bug，歸納出 4 種自動判定方法，再用演化演算法加上深度強化學習，讓 agent 在「贏下戰鬥」和「探索沒去過的地方」之間取得平衡。它在兩款商業遊戲中找到 3 個先前未知、經開發者確認的 bug。

到了 LLM 的時代，浙江大學與網易伏羲的 TITAN 讓 GPT-4o 驅動的 agent 玩兩款商業 MMORPG，並用三種自動判定（是否當機、任務是否卡住、執行是否超時）把異常整理成診斷報告。

TITAN 另外找到 4 個先前測試沒抓到的 bug，並已部署在 8 條實際的遊戲 QA 流程中。

流派二 · 從回報到重現（收到回報後）

讀玩家的回報，把當機重新走一遍

這條路線先在 Android app 上成熟。ReCDroid 用自然語言處理加上 GUI 探索；AdbGPT（ICSE 2024）讓 LLM 先把回報拆成步驟，再在畫面上依序執行，作者報告 81.3% 的重現率。不過當別人用自己的資料重新評估時，數字差異很大：

遊戲版本的代表是 BugCraft（ASE 2025）。作者從 Minecraft 官方的 bug 追蹤系統挑出 100 份單人模式的當機回報，排除 14 份無法重現的，剩下 86 份組成 BugCraft-Bench。系統分兩步：先讓 LLM 把回報整理成重現步驟，再由看得懂畫面的 agent 透過一套為 Minecraft 寫的指令集在遊戲裡執行。

流派三 · 當機紀錄分流（上線後）

從大量當機紀錄裡，挑出會擴散的那幾個

上線之後問題變了：當機紀錄不缺，缺的是判斷先修哪一個。Weeraddana、Habchi（Ubisoft La Forge）與 McIntosh 分析了 Ubisoft 遊戲上線後的當機，發現大部分當機類型只影響少數玩家，但有一小群會快速擴散。他們把這群稱為「病毒式」當機：有的一上線就爆發，有的先潛伏一陣子才擴散。

他們用前一款已上線遊戲的資料，預測新遊戲裡哪些當機會變成病毒式。結果是，比較 stack trace 的相似度，表現勝過機器學習模型，能找出超過一半的病毒式當機類型。

現在卡在哪裡

  1. 遊戲版的重現 benchmark 只有一款遊戲。BugCraft-Bench 的 86 份回報全部來自 Minecraft 單人模式。在其他遊戲上，類似流程能做到多少，目前沒有資料。
  2. 每款遊戲都要重寫操作介面。BugCraft 依賴一套 Minecraft 專用的指令集；不用這套指令集的通用電腦操作 agent，最好的是 25.5%，開源的 UI-TARS 是 0%。
  3. 遊戲比 app 多了空間和狀態。BugCraft 的作者指出，Android 的方法把畫面轉成文字處理，但遊戲需要空間推理、複雜的狀態相依和隨版本改變的機制，這些是 2D 介面的方法處理不到的。
  4. 回報本身就不完整。100 份回報裡有 14 份連人都無法重現；能重現的回報中，LLM 整理出的步驟有三分之一缺步驟、下錯指令或邏輯不通。
  5. 自報數字和重測數字落差很大。AdbGPT 自報 81.3%，兩份重測分別是 74% 和約 36%。評估資料不同，同一個工具的表現可以差到一倍以上。
  6. 探索式測試的成績多半來自注入的 bug。TITAN 的 bug 偵測率是在 9 個人為放進去的 bug 上量的；在真實、未知的 bug 上能找到多少，只能從「找到幾個新 bug」這類個案數字推估。
  7. 上線後的分流仍漏掉不少。Ubisoft 的研究中，最好的方法找出超過一半的病毒式當機類型，也就是說仍有相當比例在擴散之前沒被標出來；不過被找出的類型涵蓋的當機次數，明顯多於漏掉的。

當機至少有一個好處：它發生時沒有人會懷疑。接下來四頁的 bug 都沒有這個好處，遊戲照常執行，只是某個地方「看起來不對」。第一個要看的，是研究最多的畫面渲染。
